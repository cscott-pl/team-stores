# Data inventory

Build-order step 1. Every distinct data shape the UI displays, and every place data is read or
written. **Raw material for `docs/service-layers/` — the seams are not designed here.**

**Source:** `reference/workspace-app.jsx`, export 2026-09-08.

---

## How the prototype holds data today

No service layer, no modules, no imports. All of it is:

- **160 in-file data constants** — seed arrays and lookup tables
- **~30 factory functions** — `makeSeedStores`, `makeSeededStores`, `makeSampleLeagues`,
  `makeOrdersDataset`, `makeBankSeed`, `makeRosterOrg`, `makeBulkBank`, `makeAllOrdersColumns`, …
- **579 `useState` hooks**, 127 `useEffect`
- **10 persistence keys** in `localStorage` / `sessionStorage`
- **22 `window.__*` globals** used as a cross-component message bus

Every read is synchronous. That is the single most important fact for `src/services/`: `CLAUDE.md`
requires every service function to be async and promise-returning, so **each seam below introduces
a loading state and a failure path the design never showed** (OQ-P13).

## Core entities

### Store — the central record, ~40 fields

`id · ownership · createdByName · storeTitle · teamName · storeType · rosterProfile · teamColors ·
teamLogo · sport · contactPref · email · phone · managerName · storeOpenMode · storeOpenStart ·
storeOpenEnd · shipFirstName · shipLastName · shipName · shipStreet · shipCity · shipState ·
shipZip · shipCountry · shipOption · distributionModel · saveToAddressBook · collectTax · taxRate ·
taxMode · flatTaxRate · fundraisingEnabled · announcement · revenue · heroTheme · primaryColor ·
collectPlayerName · collectRosterNumber · curatedProducts · urgencyTimers`

Plus runtime flags layered on by `makeSeededStores`: `seeded · live · status · archived ·
products[] · __userCreated`.

**Concerns already mixed into one object:** identity, branding/theme, contact, schedule, shipping
address, tax config, fundraising, distribution model, revenue, and the product list. The service
seam should not assume this stays one record — but **do not split it during conversion**; that is
a backend-shape decision (`CLAUDE.md`: no assumptions about database shape or table ownership).

**`storeType`** distinguishes league from individual and drives label switching (`My Team` /
`My Teams`) and section visibility. Differences the design does not show → OQ-P08.

### Product — nested in `store.products[]`

`id · title · subtitle · sku · photo · status · teamSetting · source · brand · category · deco ·
decoratable · hasOrders · storeCategory · storeSubcategory · rosters[] · colorway · colorways[] ·
retail · base · pricing{} · srcKind · __pendingId`

- `status` ∈ `draft | published | live`
- `teamSetting` ∈ `team-required | team-supplied | fan-gear`
- `rosters[]` — roster ids the product is scoped to, the products↔roster join (OQ-P07)
- `photo` is a **bare filename**, resolved at render as `` `assets/products/${photo}.png` ``

### Order

`lines[] · charges{} · subtotal · poNumber · tempShipDate`, plus nested `ship{name, street,
cityLine, email, phone}` and `contact{name, email, phone}`, and the display fields
`webOrderNum · factoryOrderNum · tracking · status · dueDate`.

Generated by `makeOrdersDataset` (`:24279`); column definitions by `makeAllOrdersColumns`
(`:23169`) with 53 lines of `ALL_ORDERS_FILTER_OPTIONS`.

### League

`id · name · location · avatarColor · storeIds[] · groups[] · members[]` — where `members[]`
carries roles (`RoleBadge`) and `storeIds[]` is the league↔store join. Cross-brand span
unanswered → OQ-P02.

### Roster group → roster → player

```
group  { id, name, sport, color, rosters[] }
roster { id, name, division, players }          // players = a COUNT here
player { …in CR_PLAYERS / bank seeds: name, number, size fields, group/roster refs }
```

Note the seed stores a **count**, while `RosterPlayerTable` works with player records — two
representations of the same thing. Structure and how products/orders/freight attach → OQ-P07.

### Account profile — read-only

`ACCOUNT_PROFILE` (`:26400`): `firstName · lastName · email · countryCode · countryFlag · phone ·
country · state · city · zip · dealership · dealershipId`.

`CLAUDE.md` treats auth as an injected boundary. This is mirrored Customizer identity — Personal
Info and Security are strictly read-only, and "Edit Profile" opens
`customizer.prolook.com/account` in a new tab. **Do not implement auth.**

### Brand / tenant

`CUSTOMIZER_BRANDS` (`:617`) + `ACCESSIBLE_CUSTOMIZERS`, with the originating brand taken from the
`?brand=` URL parameter and a `primaryBrand` state. **This is the runtime brand config**
`CLAUDE.md` requires live in `src/config/` — never a build-time constant, never assuming one build
serves one brand. Whether a rep spans brands → OQ-P01.

## The 22 `window.__*` globals — cross-component reaching

`CLAUDE.md`: *props down / events up; no cross-component reaching.* Every one of these violates
that and each is a **refactor decision, not a mechanical translation**.

**Imperative navigation** (7): `__openMyCarts`, `__openSavedDesigns`, `__goToDashTab`,
`__goToPendingOrder`, `__openLaunchModal`, `__openStoreGuide`, `__openTmPortal`
**Shared mutable state** (11): `__storeTeams`, `__prodCats`, `__storeCatCfg`, `__catalogTemplates`,
`__prostockItems`, `__rosterDupes`, `__rosterNaming`, `__rosterNumbers`, `__sysEmailState`,
`__tmInvites`, `__tcStore`
**Transient flags** (4): `__awbState`, `__crCanReplay`, `__pteFilterCollecting`,
`__startOnboardingDemo`

Likely destinations: the navigation set → `vue-router`; the shared-state set → Pinia stores; the
flags → local component state or store actions. **Logged, not decided** — and each will be logged
individually as it is unwound.

Also used: `CustomEvent` dispatch on `window` for `closereport:replay` and `setupguide:open`.

## ⚠️ Seed data is non-deterministic

`workspace-app.jsx:27918`:

```js
revenue: b.revenue != null ? b.revenue : Math.round((Math.random() * 1800 + 200) * 100) / 100,
```

Store revenue is randomised per load whenever not explicitly seeded, and it feeds the Overview
KPI totals. **Observed directly:** two loads gave Total Revenue **$69,589** then **$69,420**, and
Orders **1,513** then **1,509**.

There are 7 `Math.random()` sites in total (also id generation and simulated upload progress), and
47 `Date.now()` / 59 `new Date()` sites, so relative dates ("3 days ago", "0 days left") drift
over time too.

**Consequences:**

1. **No numeric or pixel comparison of the Overview KPIs can ever pass.** Compare layout,
   typography, spacing and formatting — not values. This is a hole in `AGENTS.md` fidelity
   checklist item 1 and should be noted there.
2. **`src/mock-data/` must be deterministic.** Fixed fixtures, not randomised factories —
   otherwise our own regression comparisons are unstable too. This is not a fidelity divergence:
   the *design* of the numbers is preserved, only their instability is dropped.
3. **Date-relative displays need a fixed reference date** in fixtures, or they will drift.

## Where this goes next

Nothing here designs a seam. When `docs/service-layers/` is written, the read/write points above
group roughly into: stores, products, orders, rosters, leagues, vault, reports/analytics
(*separate from transactional data* per `CLAUDE.md`), templates, account/identity (injected), and
brand config (runtime). **That grouping is a proposal, not a decision.**
